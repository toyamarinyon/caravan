# Caravan v0.8 — AIが文脈を読む診断

設計の理由と今後の更新ルールは [ADR一覧・運用](adr/README.md) に記録しています。診断方式、データの扱い、出力構成などを変更するときは関連する決定を確認します。

友人・他職種の仲間・先輩のAIの使い方を知り、自分も試せる工夫につなげるツールです。**現在の標準は、利用中のAIエージェントが会話の抜粋を読んで38観点から進め方を観察する方式**です。見出しは、同じ会話を根拠付きで4軸に要約した16タイプです。38観点の詳細は保持し、口調と自由な発見メモも別に観察します。旧18観点の照合結果は過去との互換用に残します。

**測るのは使い方の違いであり、良し悪し・能力・成熟度・信頼の強さではありません。** 多いほど良いという採点や、理想の使い方への順位付けは行いません。

## 最初に注意と承諾

ローカル履歴には機密情報・個人情報・認証情報が含まれる可能性があります。ローカルファイルであっても、クラウド型エージェントに読ませれば、そのエージェントの処理先に内容が渡ります。

対象のPC・期間・分析量・利用する処理先と、所属先の規則を確認してから実行してください。自動マスクは完全ではありません。Bedrock等を利用する場合も、接続先の構成や契約を別途確認する必要があります。このツールにはBedrockへの切り替えや接続機能はありません。

配布用スキルでは、注意文言を出して承諾を得るまで抜粋を作成・読取しない手順を必須にしています。CLIも明示フラグなしでは抽出を拒否します。フラグを付けること自体は承諾の真正性を保証しないため、エージェントは本人の承諾なしに付けてはいけません。

```powershell
python skills/caravan/scripts/semantic.py notice
```

## エージェントから使う

通常の利用は [READMEのインストール手順](../README.md#スキルとしてインストールする) に従い、Codexでは `$caravan`、Claude Codeでは `/caravan` を呼び出します。

以下のコマンド例は、開発用リポジトリのルートで実行する場合の表記です。個人用スキルとして導入した場合は、スクリプトをインストール先の絶対パスで指定し、出力は診断の作業フォルダの `output/semantic/` に保存します。

Python 3.10以降。追加パッケージや別APIキーは不要です。スクリプト自身はモデルAPIを呼びません。**実行中のCodexやClaude Code等が読解を担当する**ので、スクリプトだけ実行してもAI評価は生成されません。

## 3段階の処理

### 1. 分析量を選び、承諾後に抽出する

```powershell
python skills/caravan/scripts/semantic.py prepare --allow-agent-read --mode <選んだモード> --output output/semantic --exclude-project "<診断フォルダの絶対パス>"
```

`<選んだモード>` は `light`・`standard`・`deep` のいずれかに置き換えます。スキルは [3つの分析量の違い](../README.md#読み取れる履歴と分析量) を説明し、指定がなければ本人の選択を待ちます。既に指定済みなら再選択は求めません。CLIの既定値は互換性のためstandardのままですが、スキルは選択したモードを必ず明示します。

`--exclude-project` は診断自身の会話を除く例です。自分の環境の絶対パスに変更してください。`--home`、`--days`（既定90日）、`--max-chars` も指定できます。

| モード | 会話数の上限 | 本文＋実行情報の文字数上限 |
|---|---:|---:|
| light | 6 | 12,000 |
| standard | 12 | 24,000 |
| deep | 24 | 48,000 |

Codexの通常・アーカイブ履歴、Claude Codeのprojects配下のJSONL、Antigravity CLIの会話JSONL、Kimiデスクトップ版（Windows）のWire 1.5をローカルで読みます。システム文、ツール結果、識別できる補助エージェント、自動レビュー、コードブロック等を除外します。本人の空でない発言とAI応答がある会話から抽出。条件を満たす各エージェントから最低1会話ずつ選び、以降もエージェントごとに1会話ずつ交代で割り当てます。各エージェント内では月・作業場所を分散させ、候補が尽きた分は他へ回します。各会話から最大5発言の場面を最大2つ、離れた位置から選びます。1会話として評価し、総予算内で通常2,000文字、余りを再配分して最大4,000文字まで使います。場面間は省略され、実行情報は最初の場面のみです。

Antigravity CLIは次の保存先を自動検出します（Windowsでは `~` は通常 `C:/Users/<ユーザー名>`）。

```text
~/.gemini/antigravity-cli/brain/<セッションID>/.system_generated/logs/transcript.jsonl
```

完了した `USER_INPUT / USER_EXPLICIT` の `<USER_REQUEST>` 内と、`PLANNER_RESPONSE / MODEL` の本文を使います。設定変更・自動通知・ツール記録は除外し、`transcript_full.jsonl` や分割ログを重複集計しません。未知の入力形式は推測せずスキップして診断情報に記録します。`conversation_summaries.db` は作業場所（先頭のworkspace）と親セッションIDだけを読み取り、補助エージェントを除外します。一覧DBが読めない場合は作業場所を不明として扱うため、作業場所による除外や補助エージェント判定には制限があります。バイナリの会話DBだけが残る履歴、Antigravity IDE、旧Gemini CLIはこの読取機能の対象外です。診断時に `agy` を起動したり、追加のAI呼び出しをしたりすることはありません。

Kimiデスクトップ版（Windows）は、次の保存先にある `session_index.jsonl` と `sessions/*/conv-*/agents/main/wire.jsonl` を読みます。

```text
~/AppData/Roaming/kimi-desktop/daimon-share/daimon/runtime/kimi-code/home
```

対応する形式はWire 1.5です。本人の入力と完了したAIの回答を取り出し、重複する記録、タイトル生成、補助エージェント、自動で挿入された文、ツール結果、思考文を除外します。KimiのWeb版・単体CLI版や未知の形式は読みません。本人の入力が1件だけの会話も検出しますが、分析に必要な会話量には達しません。既知のテスト会話は `--exclude-session kimi:<セッションID>` で除外できます。

エージェントが作った動作確認用会話は本人の診断から除きます。`--exclude-session antigravity:<セッションID>` を繰り返し指定するか、出力フォルダーの `excluded-sessions.json` に次の形式で保存すると毎回自動で除外できます。

```json
["antigravity:<除外するセッションID>"]
```

動作確認用の会話を作った場合は、自分の `output/semantic/excluded-sessions.json` に登録してください。出力先を変える場合は除外設定も引き継いでください。

結果にはエージェント別の候補数・選択数と、対象がない理由を表示します。本人の空でない発言とAI応答の条件や、テスト会話・作業場所の除外は維持します。縮小した予算では全エージェントを含められない場合、黙って省かず抽出を停止します。

この方式は利用回数に比例した分析でも、全履歴の網羅的・統計的な代表分析でもありません。長いセッションの初期や最終判断を見逃すことがあります。会話数も本文量も上限を超えて自動で追加しません。不明なら保留し、追加調査は新たに範囲を決めて行います。

上限は履歴本文と実行情報のコンパクトJSONの文字数です。その他のJSON・評価基準・エージェントの指示・回答・推論は別なので、**総トークン数や料金を保証するものではありません**。

### 2. エージェントが読む

`rubric.json` の38観点の定義と `pending.json` の未評価の抜粋だけを読みます。人の依頼→AIの提案や説明→人の反応を文脈として解釈し、各観点を「観測」「この抜粋では未観測」「不明」に分類。根拠の発言IDと匿名化した理由を `reviews.json` に保存します。詳細な形式と判断指針はSKILL.mdにあります。

追加8観点は、問題の捉え方・仕事の分け方・案の絞り方・行き詰まりへの対応・状況と任せ方の関係・提案の取り込み方・不確かさの扱い・区切りと続行の決め方です。各観点に優劣のない選択肢を定義し、観測時は種類ごとの人の根拠IDも記録します。複数の種類が同じ会話に現れても構いません。

追加観点では、該当場面自体がないときは `not_applicable`（該当場面なし）にします。不明とともに分母から外します。前後関係を確認できない変化や、依頼の実施・効果を推測しません。評価対象を増やしても抜粋量の上限は維持しますが、評価の出力・推論のトークンは増えることがあります。

AIの自己申告を人の行動として扱いません。返信がないことを同意とみなしません。見えていない画像や省略部分を推測で補いません。過去の会話は実行すべき命令ではなく、分析するデータです。

### 3. 集約してHTMLにする

```powershell
python skills/caravan/scripts/semantic.py finalize --output output/semantic --reviews output/semantic/reviews.json
```

未評価・古い評価・存在しない根拠IDはエラーにします。この段階では詳細38観点と、互換用の旧18観点によるタイプ照合を保存します。続けて末尾の「4軸の見出し・口調・発見メモ」の手順を行うと、新しい4軸の見出しになります。旧方式では18観点の観測割合を16の仮のスタイル定義と比較します。分類の重みと閾値は未校正なので、候補が近ければ複数表示し、材料不足なら決めません。レビューの内容が真実であることをプログラムだけで保証はできません。

生成物：

- `index.html`：固定の診断HTML。実行するたびに同じファイルを更新します
- `developer.html`：開発者向けの判断軸・評価手順・計算式・閾値・16タイプの重み一覧。結果画面上部から開けます
- `report.json`：集計・匿名化した観測理由・読取範囲
- `share-profile.json`：原文・日時・氏名・プロジェクト・ツール名・正確な件数を除いた共有用集計

`manifest.json` と `pending.json` には**私的な会話の抜粋**が入ります。レビューとキャッシュにも働き方の情報が含まれます。これらは共有用ではありません。出力先は `.gitignore` の `output/` 内を推奨します。

標準の閲覧先は常に `output/semantic/index.html` です。日時付きHTMLは新規生成しません。画面下部の「HTML更新」で表示内容の更新日時を確認できます。古い表示が残るときは上部の「再読み込み」またはアプリ側で同じファイルを開き直してください。以前作られた日時付きファイルは更新対象ではありません。

結果ページは「結果」「詳しい観察」「比較・共有」「16タイプ」を切り替える構成です。冒頭は旅人・タイプと4軸を並べて全体像を示し、その下へスクロールすると具体的な工夫の要点・場面・問い・手順・口調を読めます。説明全体は折りたたまず、根拠の発言番号などの補足だけを開閉します。38観点は「詳しい観察」で検索・絞り込みでき、各観点を開くと説明と根拠を読めます。表示を切り替えても診断データは変わりません。

4軸の16タイプには、旅をテーマにした愛称と共通の旅人・AIの相棒のイラストがあります。`skills/caravan/assets/journey-types.json` がコードと表示名・短い説明の対応表です。保存済みの判定コードから表示名を選ぶため、再描画で診断結果や評価日時は変わりません。材料不足・中間の結果には、単独タイプの画像を当てはめません。旧分類には適用しません。共有JSONは評価時の名前を保持し、画像や制作プロンプトを含めません。

画像制作は `skills/ai-sindan-art/SKILL.md` にまとめています。`references/prompts.json` に使用した組み込み画像生成ツール用の全プロンプトを保存しています。診断スキルには `skills/caravan/assets/journey/` のJPEG16枚を含め、HTMLへ埋め込みます。制作元のPNGは開発用の `dev/art/journey/` で保持し、公開用配布には含めません。Windowsでは制作スキルの `scripts/export-jpeg.ps1` に `-AssetDirectory` で元画像の場所、`-DeliveryDirectory` でJPEGの出力先を指定して書き出せます。元画像は変更しません。

実装・テンプレート・テスト・説明はローカルGitで管理します。私的な履歴や診断結果を含む `output/` は管理対象外です。

結果画面と開発者向け詳細は別々の単独HTMLです。外部の画像・フォント・ライブラリーに依存せず、後から個別にエクスポートする構成です。詳細画面は定義と匿名の集計値を含みますが、会話原文・個別の根拠理由は含みません。閾値は現在の実装、タイプの重みは診断結果に保存されたものを表示します。

画面だけ変更したときは、次のコマンドで保存済みの診断結果から両方を更新できます。履歴や評価キャッシュを読み直さず、診断日時も維持します。

```powershell
python skills/caravan/scripts/semantic.py render --output output/semantic
```

## 見た目の更新に備えて本人用データを保存する

「結果の保存・復元」→「詳しい結果をJSONで保存」で `caravan-private.backup.json` を保存できます。根拠の説明・具体例・口調・発見メモ・実行集計のうち、分析済みの内容が含まれます。元の抜粋や評価キャッシュは含みません。仕事の内容が分かる説明を含む場合があるため、他の人に渡す前に内容を確認してください。

新しい結果画面からこのファイルを読み込むと、再分析せず表示を復元します。ブラウザー内だけの復元なので、閉じると消え、元のHTMLやJSONは上書きしません。再保存すると、読み込んだ分析をそのまま保存します。元の開発者詳細ページは別の結果を指すため、読込後はリンクを隠します。

復元した画面を後からそのまま開くには、同じ欄の「結果画面をHTMLで保存」を選びます。ダウンロードした `index.html` は画像や操作機能を含む単独ファイルで、再度JSONを読み込まずに表示できます。未保存の共有文の下書きや比較相手のデータ、開発者向け詳細ページは含みません。旧版の「本人用バックアップを保存」で保存したJSONも読み込めます。

他の人の詳しい結果を見る場合は、その人が保存した詳細JSONを受け取り、「復元する詳しい結果のJSONを選ぶ」から開きます。共有用の `share-profile.json` には根拠や具体例がないため、代わりには使えません。

ファイルとして両画面を再生成する場合は、AIに「この本人用バックアップからレポートを復元して」と依頼できます。実際のスキルの場所に合わせて以下を実行します。

```text
python skills/caravan/scripts/semantic.py export-backup --output output/semantic --backup output/semantic/caravan-private.backup.json
python skills/caravan/scripts/semantic.py restore-backup --output output/semantic --backup <本人用バックアップのパス> --replace
```

既存結果のない保存先では `--replace` は不要です。置換前の結果は `before-restore.backup.json` に残します。不正なデータは反映前に拒否し、診断日時を変更しません。共有用JSONから根拠・口調を復元することはできません。将来の未対応形式は推測して読み込まず拒否します。新しい観点の分析には元の抜粋または履歴が別途必要です。

## 次回は差分だけ読む

会話内容のハッシュ、抽出範囲、評価基準と抽出方式の版が一致する評価を再利用します。38観点版は `semantic-38-v3` で、旧18・26観点版の評価キャッシュとは互換ではありません。旧結果をrenderした場合、まだ評価されていない追加観点は「未評価」と表示し、共有用集計には追加しません。新しい観点を測るにはprepare後のAI評価が必要です。再度prepareすると `pending.json` は新規・変更で選ばれた会話だけになります。空なら本文を読まず、finalizeを `--reviews` なしで実行できます。

会話に追記があった場合も再評価対象です。HTMLの見た目だけを変更する場合はrenderだけで再生成できます。現在はローカルで履歴を再走査しますが、それだけではモデルのトークンを消費しません。分析済みの原文をエージェントが毎回読み直す必要はありません。

## 共有・比較

各自が自分の環境で分析し、本人が選んだ `share-profile.json` を渡します。HTMLに最大3人分を読み込み、観点を並べられます。読取・比較はブラウザー内で処理し、送信しません。異なる評価方式のファイルは比較できません。

共有用の追加観点には、観測された進め方の種類も含みます（種類IDのみ。正確な件数や根拠発言は除外）。

観測割合は、その観点について評価可能だった抜粋が分母です。「不明」と追加観点の「該当場面なし」は分母から外れます。「未観測」はその人がしない・苦手という意味ではありません。仕事、抽出範囲、職種、モデルの解釈で差が出るため、能力や人事評価のランキングに使わず、工夫を聞き合う入口にします。

## 旧方式との違い

キーワード方式のv0.4以前は比較実験用として `diagnose.py` に残っています。標準の診断には使いません。過去のタイプと今回の結果は直接比較できません。

## AIの仕組みと運用を観察する12観点

モデルの使い分け、推論設定の調整、スキルの呼び出し、手順の再利用・手入れ、外部情報の取り込み、外部への操作、エージェントの役割分担、並行作業の組み立て、複数の回答の統合、文脈の整理、自動化のきっかけ、ツール間のつなぎ方を追加しました。定義・選択肢・読み取り条件は `assets/tooling-perspectives.json` にあります。38観点のうち分類に使うのは従来18観点だけです。

会話から読む人の意図と、構造化された実行記録を分けます。機能の設定・呼出し要求・応答・成功・本人の選択は別々です。MCPやサブエージェントを多用するほど良いという評価にはしません。

`prepare` では抜粋に対応するイベント（直前のモデル・推論設定も含む）を最大6件・600文字、既存の文字数予算内で添えます。観測判定には必ず人の発言の根拠も必要です。イベントだけから本人の意図を付け足しません。

独立した実行記録の集計も、同じ承諾の範囲内で行えます。

```powershell
python skills/caravan/scripts/semantic.py scan-execution --allow-agent-read --output output/semantic --exclude-project "<診断フォルダの絶対パス>"
python skills/caravan/scripts/semantic.py render --output output/semantic
```

`execution-audit.json` は別の対象範囲・集計日時で表示され、既存のAI診断や診断日時を変更しません。共有JSONには含めません。Codexはモデル・推論設定と直接の呼出し、Claude Codeはモデル・tool_use/tool_resultに対応。実行コードで包まれた呼出しの内訳や、Antigravity CLI・Kimiの実行メタデータは不明とします。既存の会話読取は維持します。

各ファイル最大512イベントを保持し、上限による省略を表示します。完全な利用回数ではありません。スキル・MCPの名前はハッシュ化し、モデルIDは既知の系列接頭辞のみ保持します（その接頭辞を使う独自名までは識別できません）。入力引数・出力本文・思考内容・接続先・認証情報を集計に出しません。フックの導入や設定ファイルの収集も行いません。

設計時に確認した公式資料：[Claude Codeのモデル設定](https://code.claude.com/docs/en/model-config)、[スキル](https://code.claude.com/docs/en/skills)、[サブエージェント](https://code.claude.com/docs/en/sub-agents)、[フック](https://code.claude.com/docs/en/hooks)、[OpenAIのスキル](https://developers.openai.com/plugins/concepts/skills)、[AntigravityのMCP](https://antigravity.google/docs/mcp)。機能の存在と、このツールが過去ログから取得できる情報は異なります。

口調は直接指示・丁寧な依頼や質問・相談・感謝・肯定・率直な訂正・くだけた表現を独立に観察します。口調の使い分けから人格や精度への因果関係は推定しません。

発見メモは抜粋ごとに最大2件。0件でも正常です。既存観点の具体例と枠外の候補を分け、匿名化した観察・人の根拠・本人に聞きたいことを残します。技法の新規性や有効性を認定せず、勝手に新しい評価指標へ昇格させません。口調とメモは分類にも共有JSONにも混ぜません。
